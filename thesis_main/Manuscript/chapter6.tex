\section{Modeling}\label{modeling}

This chapter covers the CRISP-DM modeling phase for the prepared open-market dataset. Chapter 5 described how the training data was assembled. This chapter explains how the three models were specified, fit, and tuned in the current pipeline. Detailed evaluation results are discussed in Chapter 7.

\subsection{\texorpdfstring{\textbf{Model Selection Rationale}}{Model Selection Rationale}}\label{chapter6-model-selection-rationale}

The study used three models because each one served a different role in the analysis. Ordinary Least Squares (OLS) was used as the interpretable hedonic baseline rooted in implicit-price theory \parencite{rosen1974}. Random Forest was included because it can capture non-linear relationships and feature interactions without requiring a fixed functional form \parencite{breiman2001}. XGBoost was included because gradient boosting usually performs well on structured tabular data and was expected to be the strongest predictive model in the final comparison \parencite{chen2016}. Chapter 3 already introduced these models conceptually. The focus here is the actual fitting setup used in the saved implementation.

\subsection{\texorpdfstring{\textbf{Train/Test Split}}{Train/Test Split}}\label{train-test-split}

The modeling script took the 1{,}491-row output from Chapter 5 and split it into training and test subsets using an 80:20 ratio. This produced 1{,}192 training rows and 299 test rows. The split used random\_state = 42 so that the same rows would be assigned to the same fold every time the script was rerun.

The code also passed market\_segment to the split function as a stratification variable. In practice, this did not change the final class balance because the modeling dataset had already been filtered to open\_market only. The stratification argument remained in the script as a carryover from the broader ABT design, but after the open-market restriction it acted only as a consistency check.

All three models were fit on the same target vector, log\_price. This kept the training target consistent across OLS, Random Forest, and XGBoost. Chapter 7 reports the back-transformed error metrics for comparison.

\subsection{\texorpdfstring{\textbf{OLS Hedonic Baseline}}{OLS Hedonic Baseline}}\label{ols-hedonic-baseline}

The OLS baseline was fit in \emph{statsmodels} using the X\_ols matrix and the log\_price target. This was the most constrained specification among the three models because it had to remain stable enough for coefficient interpretation. The final saved summary in Models/ols\_summary.txt used 1{,}192 training observations and 39 modeled terms after the constant was added.

The OLS feature set followed three decisions from the modeling log. First, dist\_talisay\_tabunok\_m was removed because it was highly collinear with adjacent CBD-distance variables. Second, is\_mactan\_island, bir\_zonal\_rr\_log, and is\_vacant\_lot were removed from X\_ols because they duplicated information already represented by dummy variables or their raw counterparts. Third, the raw area fields were replaced with a log-scale area term so the baseline would follow a log-linear hedonic form rather than a raw linear size effect. In the current script this meant dropping lot\_area\_sqm, floor\_area\_sqm, and area\_sqm from X\_ols, then adding log\_floor\_area\_sqm back as the retained size term.

These changes were not applied to the tree-based models. Random Forest and XGBoost were allowed to keep the full X\_full matrix because tree splits are more tolerant of redundant and correlated predictors. The tighter OLS feature set was therefore a stability choice, not a general claim that the dropped columns had no predictive value.

The condition-number check showed why this narrower OLS matrix was necessary. The earlier unstable form had a condition number of about $1.04 \times 10^{16}$. The saved OLS summary reported a condition number of $7.98 \times 10^{6}$. This was still large, but it was much lower than the earlier near-singular specification and was sufficient for the baseline role assigned to OLS in this study.

\subsection{\texorpdfstring{\textbf{Random Forest}}{Random Forest}}\label{random-forest}

The production Random Forest model was fit with 300 trees using \emph{scikit-learn}'s \emph{RandomForestRegressor} \parencite{breiman2001}. The saved object used n\_estimators = 300, random\_state = 42, and n\_jobs = -1. Other controls were left at the library defaults in the current environment. In the saved model object this resolved to settings such as max\_depth = None, min\_samples\_split = 2, min\_samples\_leaf = 1, and max\_features = 1.0.

The model was trained on X\_full rather than X\_ols. This let the ensemble learn from the complete structural, locational, administrative, and accessibility feature set without the stricter collinearity controls imposed on the OLS baseline. No scaling step was applied before fitting.

\begin{center}\rule{0.5\linewidth}{0.5pt}\end{center}

\subsection{\texorpdfstring{\textbf{XGBoost}}{XGBoost}}\label{xgboost}

The baseline XGBoost comparator was fit with the \emph{XGBRegressor} implementation from the \emph{xgboost} package \parencite{chen2016}. The saved baseline object used n\_estimators = 300, learning\_rate = 0.05, max\_depth = 6, random\_state = 42, objective = reg:squarederror, and verbosity = 0. Other controls were left at the estimator defaults.

Like the Random Forest model, XGBoost used the full X\_full matrix and the same log\_price target vector. This kept the comparison fair across the two tree-based models. The baseline configuration was intentionally simple because it already performed well on the prepared dataset and did not require an extensive parameter stack to produce a competitive fitted model.

\subsection{\texorpdfstring{\textbf{Hyperparameter Tuning}}{Hyperparameter Tuning}}\label{hyperparameter-tuning-ch6}

Hyperparameter tuning was implemented in a separate script, thesis\_main/Scripts/tune\_models.py. The current confirmation workflow used a 5$\times$3 repeated cross-validation design on the same 1{,}192-row training subset used by the production pipeline, with RMSE-first refitting so that the saved comparison stayed aligned with the deployment objective in total property price.

For Random Forest, the search was narrowed around the deployed baseline regime through a baseline-centered grid. The best tuned configuration saved by the script used n\_estimators = 400, max\_depth = None, min\_samples\_split = 2, min\_samples\_leaf = 1, and max\_features = 0.8. For XGBoost, the best tuned configuration used n\_estimators = 200, learning\_rate = 0.07, max\_depth = 7, min\_child\_weight = 5, subsample = 0.9, and colsample\_bytree = 0.8.

The tuned models were saved as rf\_tuned.pkl and xgb\_tuned.pkl, but they were not retained as production models. When the saved artifacts were evaluated on the held-out 299-row test set, the baseline Random Forest still delivered the strongest overall result with $R^2 = 0.807$. The confirmation-tuned Random Forest reduced MAPE but fell to $R^2 = 0.680$, while baseline and tuned XGBoost reached only $R^2 = 0.492$ and $R^2 = 0.557$, respectively. The baseline Random Forest configuration was therefore retained as the sole production model because none of the tuned or boosted alternatives improved out-of-sample overall performance.

\subsection{\texorpdfstring{\textbf{MCRAI Stage 2 Weight Derivation}}{MCRAI Stage 2 Weight Derivation}}\label{mcrai-stage2-weight-derivation}

The Stage 2 MCRAI composite was built from the Stage 1 OLS coefficient signs rather than using all nine categories. The final composite did not use all nine MCRAI categories. Instead, it retained only the positive-coefficient OLS categories and renormalized them into a four-part weight vector. The saved weights file in Models/mcrai\_stage2\_weights.txt reported the final implementation weights as 0.401 for mcrai\_education, 0.310 for mcrai\_grocery, 0.199 for mcrai\_recreation, and 0.102 for mcrai\_transport.

Security, tourism, and retail\_density were not used in the composite even though they remained in the model as standalone feature columns. The same was true for finance and health, which stayed in the component set but did not receive positive-composite weights. In other words, the composite index became a narrower summary measure, while the full models still learned from the full set of category-level MCRAI inputs.

An earlier branch of the project had tested SHAP-based weight derivation from the Random Forest model. That approach is recorded in Decisions 14 and 15, but it is now historical only. The controlling specification for the current manuscript is the positive-only OLS composite written to the saved Stage 2 weights file.

\subsection{\texorpdfstring{\textbf{SHAP Setup}}{SHAP Setup}}\label{shap-setup}

SHAP was configured after model fitting for the two tree-based models using \emph{shap.TreeExplainer} \parencite{lundberg2017}. In the current implementation, the explainer was applied to the held-out test set for the saved baseline Random Forest and XGBoost models. The script then computed mean absolute SHAP values by feature and exported beeswarm summary plots to the EDA folder.

This setup was used only for the tree models. The OLS baseline already had an interpretable coefficient structure, so SHAP was not necessary for that part of the pipeline. The SHAP step in Chapter 6 therefore served as the technical bridge between model fitting and the explainability analysis discussed in Chapter 7.
